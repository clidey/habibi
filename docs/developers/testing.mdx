# Testing

## Required checks

```sh
pnpm run check
```

This runs strict TypeScript checking, source-reference checks, the client
regression suite (Node's built-in `node:test`), and `cargo clippy` plus
`cargo test` for the whole Rust workspace, which includes skill-manifest
validation. Rust tests are unit tests in the crate that owns the behavior. Add
focused regressions for connector, parser, cache, permission, and
security-boundary changes. Tests must not touch the network, the credential
store, or a terminal; use the injectable backends the services provide.

CI runs the Rust checks on macOS, Windows, and Linux. That is the main evidence
for Windows and Linux today: those builds have not yet been run on real
desktops.

The `App` workflow (`.github/workflows/app.yml`) goes further on every pull
request. On each OS it builds the real app bundle (`.app`, NSIS installer,
`.deb` and AppImage), checks what the bundle ships
(`scripts/ci/check-bundle.mjs`: the UI, skills and terminal assets are there;
no Node runtime, source maps or local state), installs it, and launches it
against a throwaway data folder (`scripts/ci/smoke-app.mjs`). The launch must
reach the Rust backend over IPC, and on macOS the launcher must be a key panel.
Nightly and on demand it also runs the browser UI checks below on all three
OSes. Every run uploads screenshots and logs as artifacts for review; nothing
compares them.

## Browser UI checks

Install the WebKit test browser if needed, then run the workspace checks:

```sh
pnpm exec playwright install webkit
pnpm run check:ui
```

The checks serve the UI to a browser with an isolated data root, fictional data,
and fixtures for personal sources. They cover layouts, theme modes, window sizes, and
interactions such as Notes drag-and-drop and contextual editing.

To focus a layout investigation on one workspace:

```sh
HABIBI_UI_WORKSPACE=notes pnpm run check:ui
```

## Native checks

Per-OS behavior is covered by unit tests in `habibi-platform`, `habibi-desktop`,
and `habibi-files`, which run on each CI system. For example, the file-tools
tests check PDF page order, rotation and merging, compressed copies, image
resizing, input bounds, and OCR with the platform engine. Run them for one crate
with:

```sh
cargo test -p habibi-files
```

Features that need the real window system (global shortcut, tray, overlays,
clipboard watching, permission prompts) still need a manual check in
`pnpm run tauri:dev`.

## Safe screenshots

Repository screenshots use the sealed fictional-data demo mode:

```sh
pnpm exec playwright install webkit
pnpm generate:demo-screenshots
```

To refresh selected captures, pass their filenames without the extension:

```sh
pnpm generate:demo-screenshots --only=emoji-picker,clipboard-history,focus-timer
```

The capture script uses a temporary data root and browser profile. Browser-only
fixtures in `scripts/demo-capture-fixtures.mjs` provide fictional agent sessions,
cluster resources, and desktop utilities over the sealed demo. No native clipboard,
Reminders, timer, terminal, or cluster connection is used. Window captures have
transparent corners; the documentation theme supplies their shadows.

Never record real mail, clipboard contents, chat exports, keys, or private
screens into committed fixtures. Keep personal data directories outside the
test service's data root.

## Documentation checks

Run `pnpm run docs:check` for page metadata, links, assets, and MDX compilation.
Run `pnpm run docs:build` for a deployable static site. See
[Maintain the docs](/developers/documentation).

## AI file workflow tests

A live fixture suite passed with **`gpt-6-luna`** on 6 November 2026, before the
move to the Rust backend. It checked:

- Forty-file content-based renaming, actual apply, and Undo.
- Forty-file folder organization, actual apply, and Undo.
- Image compression and a valid PDF merge preview.
- Invoice CSV extraction grounded in fictional PDF text.
- Evidence-based document selection, storage explanation, and duplicate reporting.
- A seventeen-minute timer and a dated Apple Reminder proposal.
- Opted-in duplicate cleanup with a real Trash/Undo round trip.
- AI-selected PDF page order and rotation with a valid output preview.

The Rust file-tools tests (`cargo test -p habibi-files`) check plan validation,
approvals, PDF page order, rotation, extraction, compressed copies, image
dimensions, overwrite refusal, and Trash handling with fixtures. Browser checks
cover `@` selection, content-sharing controls, cancellation, responsive layouts,
and reviewed inline utility actions. These checks establish the supported paths;
they do not guarantee every model response or every document format will
produce a useful plan.
